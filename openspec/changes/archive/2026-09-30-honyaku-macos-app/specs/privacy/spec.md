## ADDED Requirements

### Requirement: All runtime network calls are audited and blocked
The system SHALL make no outbound network calls during normal operation (transcription, cleanup, diarization, paste). Network access is permitted only during model downloads initiated by the user. In debug builds, a URLSession delegate SHALL assert on any unexpected outbound network request, causing an immediate test failure.

#### Scenario: App is in use with no active model download
- **WHEN** the user triggers push-to-talk and the full pipeline runs
- **THEN** no outbound network requests are made by any component of the app (WhisperKit, LLM.swift, SpeakerKit, or app code)

#### Scenario: Third-party SDK attempts an unexpected network call
- **WHEN** any bundled framework (WhisperKit, LLM.swift, SpeakerKit) makes a network request outside of an explicit user-initiated model download
- **THEN** in debug builds the network audit delegate raises an assertion failure; in release builds the entitlement scope blocks the request

---

### Requirement: App data files are excluded from all backup mechanisms
The system SHALL mark all data files it creates — including `history.json`, all files under `~/Library/Application Support/Honyaku/`, and any temporary audio files — with `URLResourceValues.isExcludedFromBackup = true`. This prevents these files from appearing in Time Machine backups, iCloud Drive sync, or any other macOS backup mechanism.

#### Scenario: App data directory is created on first launch
- **WHEN** Honyaku creates its Application Support directory for the first time
- **THEN** the directory and all files within it are flagged as excluded from backup immediately upon creation

---

### Requirement: A Privacy Manifest declares the app's data practices
The system SHALL include a `PrivacyInfo.xcprivacy` Privacy Manifest in the app bundle declaring:
- Microphone usage reason
- That no user data is collected or transmitted
- That no third-party SDKs that collect data are bundled
- The specific required reason APIs used (e.g., `NSPrivacyAccessedAPICategoryFileTimestamp`, pasteboard access)

#### Scenario: App is submitted for notarisation or App Store review
- **WHEN** the build is submitted for notarisation
- **THEN** the Privacy Manifest is present and accurately describes the app's data practices

---

### Requirement: Operating system logging does not contain user content
The system SHALL NOT write transcript text, raw audio metadata, speaker labels, or any user-generated content to macOS Unified Logging (`os_log`). Log messages SHALL be limited to operational status (e.g., "transcription started", "cleanup completed in 1.2s") with no payload data.

#### Scenario: Transcription completes
- **WHEN** WhisperKit returns a transcript
- **THEN** the system logs operational metadata (duration, model tier) but not the transcript text itself

#### Scenario: Crash report is generated by macOS
- **WHEN** the app crashes
- **THEN** no transcript text or audio content appears in any os_log stream that would be included in a crash report

---

### Requirement: Xcode Organizer crash reporting is disabled
The system SHALL NOT enable Xcode Organizer crash reporting or MetricKit diagnostic uploads. Crash data SHALL stay on the user's device only and SHALL NOT be transmitted to Apple's developer dashboard or any third-party crash reporting service.

#### Scenario: App crashes on user's machine
- **WHEN** the app crashes
- **THEN** the crash report is written to `~/Library/Logs/DiagnosticReports/` only and is not uploaded to any external service

---

### Requirement: App quit cleans up all transient state
The system SHALL, on normal quit and on receiving SIGTERM, complete or abort any in-flight pipeline, delete any temporary audio files, deregister the CGEventTap, and clear any transcript data from the system pasteboard before exiting.

#### Scenario: User quits the app while recording is in progress
- **WHEN** the user quits Honyaku while the Control key is held or the pipeline is processing
- **THEN** the pipeline is aborted, the temporary audio file (if any) is deleted, the CGEventTap is deregistered, and the app exits cleanly

#### Scenario: User quits the app while transcript text is on the pasteboard
- **WHEN** the user quits Honyaku before the pasteboard has been restored to prior contents
- **THEN** the prior pasteboard contents are restored (or the pasteboard is cleared if prior contents are unavailable) before the app exits
